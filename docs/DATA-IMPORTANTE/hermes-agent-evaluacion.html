Qué hace concretamente
💬
Gateway de mensajería
Se conecta a 20+ plataformas: Telegram, Discord, Slack, WhatsApp y más. Un solo agente, múltiples canales de entrada.
🧠
Memoria persistente
A diferencia de un chatbot sin estado, recuerda contexto entre conversaciones y crea/mejora sus propias "skills" con el uso.
🔌
Cliente y servidor MCP
Puede usar servidores MCP externos, y también exponerse como servidor MCP a Claude Desktop / Cursor vía hermes mcp serve.
⚙️
6 backends de ejecución
Local, Docker, SSH, Daytona, Singularity, Modal. Compatible con cualquier endpoint estilo OpenAI — incluido Ollama local.

Relevancia para TMC / TME
Contra el stack agentic AI $0 evaluado en jul 2026
TMC/TME ya tienen N8N (orquestación) + Ollama local (razonamiento) funcionando. Los gaps reales del stack son otros.
Se solapa vs. complementa
Capa del stackHoy en TMC/TME¿Hermes aporta algo nuevo?
OrchestrationN8N (cubre 80% del caso de uso)Se solapa — Hermes es agente conversacional, no motor de workflows visuales
ReasoningOllama local (llama3.2)Compatible — Hermes puede apuntar directo a Ollama
KnowledgeNada implementado (❌ gap)Aporta parcial — memoria persistente cubre algo, pero no reemplaza ChromaDB/RAG
ObservabilitySin tracing de IA (❌ gap prioritario)No resuelve — sigue faltando Langfuse
Action / MCPEn roadmap, no implementadoAporta — gateway MCP hacia Claude Desktop, hoy inexistente
Automatizaciones pendientes de TMC — ¿las resolvería?
  • Onboarding de proveedores, moderación, pricing dinámico, detección de fraude: ya están pensadas para N8N + Ollama. Hermes no las reemplaza ni acelera — son workflows estructurados, no conversación libre.
  • Soporte automatizado (FAQs): es el caso donde más encajaría un agente conversacional con memoria — pero N8N + Gmail MCP + Ollama ya cubre esto sin agregar una pieza nueva.
⚠️ Conclusión de esta pestaña: instalar Hermes hoy sumaría una pieza más al stack sin resolver ninguno de los dos gaps prioritarios (Knowledge completo, Observability).

Recomendación final
🚦 Esperar — no instalar todavía
Se solapa con N8N sin resolver el gap prioritario del stack (Observability), y correrlo bien con memoria completa (contexto ~64K) exige más recursos de los que tiene el Chromebook sin GPU.
Factibilidad técnica en este Chromebook
✅
Instalación
Vía script (curl ... | bash), requiere Python 3.11, Node.js, ripgrep y ffmpeg. Todo instalable en Crostini sin drama.
⚠️
Hardware, sin GPU
No exige GPU para correr el agente en sí. El límite real es el modelo: llama3.2 en CPU ya está al tope con contextos chicos.
🧠
Contexto recomendado
Hermes recomienda ~64K tokens de contexto para que la memoria funcione bien con tool-calling — muy pesado en CPU pura.
🔁
Cuándo reconsiderarlo
Si en el futuro se necesita un gateway MCP hacia Claude Desktop con memoria propia — ahí sí vale la pena retomar esta evaluación.
Orden de prioridad recomendado
  • 1º  Langfuse — observability de N8N + Ollama, resuelve el gap más urgente. $0.
  • 2º  ChromaDB local — RAG sobre docs TMC para el agente de prospecting. $0.
  • 3º  Hermes Agent — recién ahí, si sigue haciendo falta un gateway MCP con memoria propia.
